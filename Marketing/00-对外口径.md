长春息壤科技有限公司是一家专注于数据库管理与数据应用的基础软件企业，以数据库技术为核心，围绕数据存储、管理、安全访问和应用支撑开展自主研发，致力于为数字化业务和智能化应用提供数据基础设施。【操作系统、中间件、硬件等属于技术研发能力或未来可能方向，不作为当前主营业务对外写成已成型产品体系。】

息壤科技以数据库内核研发和数据管理技术为核心，围绕数据库服务运行、数据访问、安全审计及业务应用支撑，构建自主研发的软件技术体系。核心研发语言为 C/C++、C#，具备数据库服务端内核研发、数据库协议处理、通用网络服务运行时与领域语言设计与开发能力。【技术能力与对外销售的商业产品须区分；不得将技术能力一概写成独立产品。】

## 当前战略主线

- **信创方向**：信创是息壤科技有限公司的市场重点。【针对资本叙事，信创方向的主市场进入门槛高、攻坚难度大，但其市场规模明确，竞争对手清晰】。息壤科技产品自主可控，完成信创产品适配与认证成果。在信创方向，息壤科技坚持差异化市场策略，利用自身技术特点，重点面向 **AI原生防线**、**生产数据库信创**、**渐进式解决方案**方向。
- **AI 原生方向**：以 AI4DB、DB4AI 为产业背景，结合息壤的多模、多数据结构和异构计算能力，优先探索 **AI4Science** 与 **AI4Engineering**。【对外候选按本文已列出的表述写成肯定句。证据未齐的条目在内部台账保持 B 类，不在对外稿中写尚未证实。A 类与 U6 的定义不因本条改变。】
- **多数据结构生产数据库信创**：信创数据库按照数据结构需求可分为两类，第一种，关系型数据库为主，异构模型和数据类型可通过关系模型解决，且对性能和质量影响不高。第二种，在关系模式数据库基础上，对异构模型和数据类型依赖高，且对性能和质量要求高。XRDB主要针对第二种需求，例如BOM、全面预算等场景，这些场景对KV、树、链表等数据结构要求高，通过对以上物化数据结构的使用可提升效率和质量。
- **渐进式解决方案**：DBPrisma 的信创替代常用语只使用下方 DBPrisma 节中的那一句，不另写一套。【须先做 PoC 验证，再作为数据库并行运行、验证和渐进替代路径。】
- **嵌入式方向**：XXDB 面向端侧、边缘和嵌入式应用信创需求。【寻找 PoC。先验证具体场景，不使用未经核实的市场规模数字。】

## 写作规则

对外稿写本文已经列出、且术语表「对外是否使用」为「是」的内容，句子用肯定说法。未列出的不写。禁写项以 `对外禁写清单.csv` 为准。成稿、文件名和封面都不写「对外候选」。缺测试或原件时在内部台账标注 B 类并催办，不把缺口写进对外稿，也不因此停稿。A 类仍指原件或凭证。U6 仍须事实确认、证据范围和审批，本条不授予 U6。

技术方案、技术实现、实验室验证、PoC、客户试用、生产应用与商业交付不得混写；未经证据支持不写国际领先、国内领先、行业第一、完全替代、全面兼容、百分之百自主可控等夸大表述（详见禁写清单）。自主研发与核心模块自研不自动等于零第三方依赖或全产品完全自主可控。产品支持某项技术与已取得相应认证须区分；认证范围以证书原文为准。

## XRDB中DB4AI与AI4DB感念与《数据库发展研究报告2026》（报告）的对应

报告原文使用“智能体原生数据库”和“数据库智能体”。公司对外使用 DB4AI、AI4DB，并以下列能力为准。

- **DB4AI**：DB4AI利用数据库技术提升人工智能应用的开发与使用效率，优化AI的数据管理、模型训练和推理过程，并在数据库内部提供AI能力。

### DBPrisma

DBPrisma（息壤数据库串行审计安全网关）部署在现有数据库前面。企业无需修改任何一行原有业务应用的代码，只需将数据库连接地址指向 DBPrisma，即可平滑完成网关接入。平台可完全接管客户端身份校验，实现应用层账号与数据库底层账号的物理隔离。在此前提下提供 SQL 防火墙、访问控制、行为审计和数据路由。互认证与适配按下列范围表述，不写证面软件版本号：四个数据库（人大金仓、TIDB、GreatSQL、南大通用），三个操作系统（麒麟服务器操作系统、麒麟桌面操作系统、欧拉操作系统），一个信创硬件（鲲鹏）。

当前支持 MySQL 和 PostgreSQL，以及兼容这两类数据库的信创产品。开发手册里若只写 MySQL，不回改那些手册；对外稿以本句为准，不写 MySQL 或 PostgreSQL 的具体大版本。

在信创数据库替代项目方向，企业沿上述接入先完成访问控制、审计和兼容，再以多路广播等迁移能力把数据库替换做成渐进过程，在保证生产安全的基础上实现信创替代目标。本句只用于 DBPrisma。

支持基于铜锁（Tongsuo）密码库实现 TLCP 国密传输协议（GB/T 38636）以及 RFC 8998 国密 TLS 1.3，采用 SM2/SM3/SM4 国密算法，实现数据库链路国密加密。国际算法 TLS 与国密可以分段配置在客户端到网关、网关到数据库两侧。

审计导出可使用 SHA-256 哈希链（每行 `prev_hash` 与 `line_hash`）锁定记录。四维合规报告覆盖运维效率、安全威胁、性能基准、合规审计。管理接口同时提供 HTTP 与 HTTPS，只读；Prometheus 等监控系统抓取 `GET /metrics`。

单条 SQL 的重组上限 `max_reassemble_bytes` 可配置到 1 GiB（1,073,741,824 字节），默认 16 MiB；该项须重启后生效，且后端 `max_allowed_packet` 不得小于该值。来源：`DBPrisma/user/user/configuration-reference.md` 文档版本 r19（2026-07-13）。

### XXDB

XXDB（潇湘）是嵌入式数据库，XXDB以库或组件的形式集成到宿主应用程序中，通常与应用程序运行在同一进程内，由应用程序直接调用XXDB接口完成数据管理的数据库系统。

### QQDB

QQDB（青丘）是集中式数据库，QQDB的数据及其核心管理功能集中于一个逻辑数据库系统，由统一的数据库管理系统负责数据存储、查询处理、事务管理、并发控制和访问服务的数据库。
QQDB可以挂载 pago、aegis存储引擎，或两个引擎同时挂载。
pago 存储引擎支持多种数据模型，多种数据结构在底层多以堆表形式物化，用于传统业务和对数据结构要求不高的环境。
aegis 版通过数据空间原生物化多种数据结构，用于数据结构要求较高的科研和工程环境。

XRDB 共性：XRQL（息壤数据库查询语言）是 XRDB 产品系列使用的数据库查询语言。XRQL 在设计上面向关系、KV、文档、图及层次模型等数据模型；各数据模型上的具体语句与操作范围以产品实现和版本为准。层次模型与树、链表、多维数组等数据结构属于不同概念层次。XRQL 支持对树、链表和多维数组等数据结构进行相应操作，具体支持范围以产品实现和版本为准。AI 插入 SQL 解析、优化、运维、存储四个层次。以上 XRQL 与 AI 插入表述同时适用于 XXDB 和 QQDB。智能体数据存储单独表述，也同时适用于两类数据库。

语言驱动提供 ODBC，以及 Java、C#、Python SDK。合作与 PoC 文稿不写零拷贝。
