## 三、后续五篇节奏

首篇发布后，按每 5–7 个工作日推出下一篇，官网作为长期内容源，公众号承载完整文章，知乎/CSDN 承接真实问题，视频号提炼一个具体观点。每篇不强制要求四渠道同日发布。

建议次序：
- DP-T1-03：先讲 SQL 防火墙到底检查什么、不能代表什么。必须准确说明当前采用正则表达式匹配，不包装成 AST 或语义识别。
- DP-T1-04：再讲身份、IP 来源和链路保护，明确应用层账号不等于自然人身份，国密覆盖范围按部署配置核验。
- DP-T2-01：讲审计记录如何提供访问上下文，不能把行为采集说成自动威胁检测或自动事件处置。
- DP-T3-01：讲代理入口如何帮助集中管理连接关系，不能承诺所有应用零改造或连接行为无差异。
- DP-T4-01：讲迁移中的访问路径治理，明确协议/驱动兼容与 SQL/数据库行为兼容是两项独立前提；DBPrisma 不是完整数据迁移工具，SQL 方言转换未开发。

## 七、事实表达边界

- DBPrisma 当前定位为息壤数据库串行审计安全网关，部署在现有数据库前。
- 代理接入需要结合数据库类型、驱动、连接协议、连接池、事务与会话行为进行验证；不得承诺所有场景零改造。
- SQL 防火墙当前采用正则表达式匹配规则，不写成 AST 或语义识别。
- IP 黑白名单是访问来源控制，不是 SQL 语句黑白名单。
- 应用层账号与数据库底层账号物理隔离，不等于识别最终自然人身份。
- 行为审计采集不等于自动威胁检测、自动告警或自动处置。
- 数据库链路国密加密的覆盖范围按具体部署配置确认。
- SQL 方言转换是独立的未开发可扩展方向，不属于当前产品能力。
- DBPrisma 可参与迁移访问路径治理，不是完整的数据迁移工具。
- 不编造客户案例、性能数字、价格、认证范围或合规承诺。
