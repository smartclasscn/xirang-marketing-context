# DBPrisma 首轮六篇市场内容发布执行计划 V1.0

- 编制日期：2026-11-22
- 适用范围：DBPrisma 首轮六篇已审阅内容的渠道生产、发布与反馈记录
- 执行周期：2026-11-23 起，按每周一篇核心内容推进；实际发布日期可按渠道运营情况微调
- 当前状态：发布生产启动；首篇发布套件已形成
- 审阅状态：首轮六篇内容已由负责人审阅通过；本计划不新增市场审验环节
- 发布权限：本文档及渠道稿准备不代表已登录或授权操作外部平台账号

## 一、执行原则

1. 六篇文章作为一个连续主题系列发布，不拆散成彼此无关的产品功能介绍。
2. 官网作为核心内容归档位置；微信公众号发布完整文章；知乎/CSDN根据真实存在的问题发布适配回答；视频号从文章中提炼一个核心观点或演示动作。
3. 同一篇内容先形成一个核心母稿，再适配渠道版本。渠道稿不得成为新的事实源。
4. 不为了凑齐渠道数量而编造问题、案例、测试结果或客户反馈。
5. 不将 SQL 方言转换、AI 分析、自动威胁检测、完整迁移工具等未实现能力写成现有功能。
6. 发布后记录链接、发布日期、内容表现、有效咨询和客户反馈；数据不足时不设虚构目标。

## 三、每篇标准交付件

- 核心发布母稿：观点完整、产品事实统一，可作为官网文章底稿。
- 微信公众号版本：适配移动端阅读，保留完整论证和产品说明。
- 社区问答版本：围绕平台真实问题组织，不复制粘贴标题党内容。
- 视频号脚本：原则上 60—90 秒，使用真实产品画面或准确的架构示意。
- 视觉说明：明确主图、结构图、界面截图的内容和禁用元素。
- 发布记录：渠道、链接、发布时间、数据、咨询线索和反馈。

| 周五 | 记录链接、阅读互动、有效咨询和反馈，安排下一篇 | 市场负责人 |

上述是推荐节奏，不要求为完成视频或社区数量而降低内容质量。人手紧张时，优先保证官网核心稿和公众号版本。

首篇内容主张：数据库安全治理不应只关注数据库内部，也需要治理应用到数据库之间的访问路径。

首篇产品表达限定为：DBPrisma 部署在现有数据库前，提供代理接入、客户端身份校验、访问控制、SQL 防火墙、IP 地址来源控制、数据库链路国密加密和行为审计能力。不得将应用层账号解释为自然人身份，不得将审计采集解释为自动威胁检测。

## 七、效果评估

不以阅读量作为唯一判断。重点观察：
- 目标角色是否触达：安全负责人、信息中心、DBA、架构和审计人员；
- 是否带来有效互动：收藏、转发、技术问题、架构交流；
- 是否形成业务动作：产品演示、技术交流、测试环境验证、PoC 或项目线索；
- 是否暴露认知偏差：客户是否误解产品边界、部署方式或能力状态。
