# DP-T2-01 内容设计与事实映射 V0.1

- 选题：数据库审计不应只记录 SQL：还需要回答谁、何时、从哪里
- 目标角色：R8 审计与合规；协同 R4 安全运营、R3 DBA
- 核心观点：SQL 是数据库审计的重要内容，但审计价值还取决于能否将请求与可识别的身份、来源、时间、目标和执行结果等上下文关联。
- 状态：文章 V0.1 初稿；内部审阅稿，未经技术/业务审核及发布审批。

## 论证结构
1. 从“有 SQL 日志仍难回答调查问题”切入；
2. 解释 SQL 与访问上下文的区别；
3. 分析身份、时间、目标和执行结果割裂造成的调查成本；
4. 给出访问行为记录的分析维度；
5. 说明 DBPrisma 在访问链路中的采集与审计定位；
6. 以审计能力检查问题收束。

## 主张与事实状态

| 主张 | 类型 | 边界 |
| --- | --- | --- |
| SQL 是审计的重要对象，但不等于完整访问上下文 | 方法判断 | 可作为观点表达 |
| 一次访问可从时间、身份、来源、请求、目标、结果等维度分析 | 方法框架 | 不是产品字段全集 |
| 不同系统的身份标识可能不一致 | 通用技术判断 | 不作绝对化陈述 |
| DBPrisma 对经过网关的数据库访问提供行为采集与审计 | 产品事实 | 以现行口径和产品版本为准 |
| DBPrisma 可为后续审计和运行分析提供数据基础 | 价值推论 | 不承诺自动分析 |
| 具体审计字段和输出接口 | 待技术核验 | 不承诺所有版本、接口字段一致 |

## 禁止延伸
- 不得把应用服务账号等同于自然人身份；
- 不得声称完整还原每一次数据库访问的全部上下文；
- 不得将 SQL 记录等同于异常检测、威胁识别或自动事件响应；
- 不得宣称自动满足审计或行业合规要求；
- 不得承诺与任意 SIEM/SOC 平台无条件兼容。

## 发布前确认
1. 选定版本的审计样本及字段定义；
2. SQL、身份、来源、时间、目标后端、执行结果的采集来源和适用条件；
3. 时间精度、时区及请求/执行时间语义；
4. 审计输出格式与接口范围；
5. 脱敏、保存、访问控制等部署责任边界。
