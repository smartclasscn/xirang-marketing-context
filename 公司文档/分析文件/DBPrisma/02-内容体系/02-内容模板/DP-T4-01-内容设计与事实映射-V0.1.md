## 论证结构
1. 迁移首先核验两层兼容：应用驱动/连接协议是否处于 DBPrisma 当前适配范围；目标数据库是否兼容应用 SQL 与数据库行为；
2. 兼容性评估和 PoC 尽量前置，优先解决已知差异；
3. 在协议和 SQL/行为兼容条件满足时，使用统一入口组织新旧数据库并行验证；
4. 说明真实 SQL/访问行为采集对迁移验证范围识别的价值；
5. 介绍 DBPrisma 的 A 统一接入、B 多后端路由、D 流量采集审计，以及 E 管理监控接口；
6. 明确写广播不等于一致性保证，DBPrisma 不是完整数据迁移工具；
7. 将无法通过 PoC、配置或应用调整解决的差异列为独立技术评估；SQL 方言转换当前未开发；
8. 以迁移切换检查清单收束。

## 兼容性前提与主要场景
1. **连接协议/驱动兼容：** 应用使用的数据库驱动和连接协议必须处于对应 DBPrisma 产品当前适配范围内。当前已知适配方向为 MySQL 与 PG；目标数据库支持 Oracle 兼容 SQL，并不意味着 DBPrisma 可以直接承接 Oracle 驱动/协议连接。
2. **SQL 与数据库行为兼容：** 目标数据库需要对应用实际使用的 SQL、数据类型、函数、事务和会话行为具备足够兼容性。
3. **前置 PoC：** 尽量在项目早期用真实应用连接和 SQL 样本验证兼容性。多数可识别差异应在正式迁移实施前处理。
4. **访问路径治理：** 在前两项满足后，DBPrisma 可参与统一接入、多后端路由、流量采集与并行验证；写广播仅在语义、事务边界和失败处理经过专项验证后再纳入方案。

## 禁止延伸
- 不得把 DBPrisma 描述为数据迁移工具或自动迁移平台；
- 不得承诺自动完成结构转换、数据复制、增量同步或一致性校验；
- 不得将路由或写广播等同于数据库复制、双写一致性或迁移完成；
- 不得把 SQL Parser 描述为 SQL 方言转换器；
- 不得承诺所有数据库、驱动和事务场景均可无条件切换；
- 不得声称接入网关即可保证迁移零停机、零风险或自动回退；
- 不得将 SQL 方言转换写成 DBPrisma 当前能力；该方向未开发，只有在 PoC 发现无法通过现有适配、配置或应用调整解决的差异时，才作为独立扩展方向评估。

## 发布前确认
1. 应用当前使用的驱动/连接协议是否由对应 DBPrisma 产品适配；
2. 目标数据库对实际 SQL、数据类型、函数、事务及会话行为的兼容范围；
3. PoC 使用的真实应用连接与 SQL 样本、兼容性问题清单和解决结果；
4. 当前版本多后端路由规则、适用数据库范围和后端连接行为；
5. 写广播是否适用；如适用，核实其执行语义、失败处理和事务边界；
6. 访问流量采集字段、输出方式和适用条件；
7. 连接切换、已有连接和故障恢复行为；
8. 示意架构与当前产品可实现部署拓扑的一致性。
