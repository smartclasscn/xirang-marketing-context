# DP-T4-01 内容设计与事实映射 V0.1

- 选题：数据库迁移不只是数据搬运，还要管理访问路径
- 目标角色：R2 架构负责人；协同 R3 DBA、R5 研发负责人、R9 迁移实施角色
- 核心观点：数据库迁移除了数据路径，还必须规划应用访问路径、后端路由、流量观察和切换回退；二者相互关联但不能相互替代。
- 状态：文章 V0.1 初稿；内部审阅稿，未经技术/业务审核及发布审批。

## 论证结构
1. 迁移期间应用访问关系仍然存在；
2. 区分数据路径与访问路径；
3. 说明真实访问行为对迁移范围识别的价值；
4. 说明统一代理入口在迁移访问组织中的作用；
5. 介绍 DBPrisma 可参与的访问路径治理；
6. 明确其不是完整数据迁移工具；
7. 以迁移切换检查清单收束。

## 主张与事实状态

| 主张 | 类型 | 边界 |
| --- | --- | --- |
| 数据迁移与访问路径调整是不同工作面 | 方法判断 | 可作为观点表达 |
| 真实 SQL/访问行为有助于识别迁移验证范围 | 应用价值推论 | 不承诺自动发现所有依赖 |
| SQL Parser 不等于 SQL 方言转换 | 产品边界 | 方言转换未开发 |
| DBPrisma 提供代理接入、连接治理、数据路由和行为审计 | 产品事实 | 按版本和部署条件表达 |
| DBPrisma 可参与迁移期间访问路径组织 | 场景应用 | 不称完整迁移方案 |
| 多后端路由或写广播可用于迁移验证设计 | 条件性场景 | 核验规则、事务边界、失败语义 |
| 代理入口不能替代数据复制、校验和一致性验证 | 产品边界 | 必须保留 |

## 禁止延伸
- 不得把 DBPrisma 描述为数据迁移工具或自动迁移平台；
- 不得承诺自动完成结构转换、数据复制、增量同步或一致性校验；
- 不得将路由或写广播等同于数据库复制、双写一致性或迁移完成；
- 不得把 SQL Parser 描述为 SQL 方言转换器；
- 不得承诺所有数据库、驱动和事务场景均可无条件切换；
- 不得声称接入网关即可保证迁移零停机、零风险或自动回退。

## 发布前确认
1. 当前版本多后端路由规则及适用数据库范围；
2. 写广播功能的具体语义、失败处理和事务边界；
3. 访问流量采集的可用字段、输出方式和适用条件；
4. 连接切换、已有连接和故障恢复行为；
5. 示意架构与当前产品可实现部署拓扑的一致性。
