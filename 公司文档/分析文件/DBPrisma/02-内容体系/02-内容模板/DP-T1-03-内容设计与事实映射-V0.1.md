# DP-T1-03 内容设计与事实映射 V0.1

- 选题：SQL 防火墙在数据库访问链路中承担什么职责
- 目标角色：R4 安全运营；协同 R3 DBA
- 核心观点：SQL 防火墙是在数据库访问链路上对 SQL 请求实施规则检查和策略处理的一层控制，不是数据库安全的全部。
- 状态：文章 V0.1 初稿；内部审阅稿，未经技术/业务审核及发布审批。

## 论证结构
1. 从客户对 SQL 防火墙的过高或过低期待切入；
2. 区分数据库原生权限与请求级 SQL 检查；
3. 解释正则表达式规则匹配与 AST/语义识别的技术区别；
4. 说明 SQL 防火墙的覆盖边界；
5. 明确 DBPrisma 当前 SQL 防火墙采用正则表达式规则匹配；
6. 给出企业评估与上线验证问题。

## 主张与事实状态

| 主张 | 类型 | 边界 |
| --- | --- | --- |
| SQL 防火墙对 SQL 请求实施规则检查并按策略处理 | 产品事实 | 以现行口径和具体版本为准 |
| DBPrisma 当前 SQL 防火墙采用正则表达式规则匹配 | 产品事实 | 不是简单字符串等值比较，不是 AST 或语义识别 |\n| AST 与语义识别 | 未来技术方向 | 拟在 SQL 方言转换方向研究，当前不属于 SQL 防火墙能力 |
| SQL 防火墙不能覆盖绕过网关的直连访问 | 架构边界 | 可作为客观边界说明 |
| 规则效果取决于规则设计、配置和验证 | 方法判断 | 不承诺自动识别所有危险语句 |
| SQL 防火墙不能替代数据库原生权限 | 安全架构判断 | 必须保留 |

## 禁止延伸
- 不得声称识别或阻断所有危险 SQL；
- 不得宣称完整防御所有 SQL 注入；
- 不得把正则表达式规则匹配写成 AST 结构识别或语义识别；\n- 不得把 SQL Parser 等同于 SQL 防火墙或安全规则；
- 不得宣称覆盖绕过网关的数据库直连；
- 不得将策略拦截等同于数据库原生权限控制；
- 不得使用未经核验的规则数量、检测率或拦截率。

## 发布前确认
1. SQL 防火墙规则类型、条件和动作的实际范围；
2. SQL Parser 与防火墙规则检查的准确处理链；
3. 不同数据库协议及语句类型的支持边界；
4. 命中策略后记录、放行、拦截等动作的配置方式；
5. 规则测试、灰度启用和回退的产品操作依据。
