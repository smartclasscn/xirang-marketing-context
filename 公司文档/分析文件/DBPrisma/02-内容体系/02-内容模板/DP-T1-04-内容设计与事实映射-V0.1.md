# DP-T1-04 内容设计与事实映射 V0.1

- 选题：数据库访问安全中的身份、来源与链路保护
- 目标角色：R4 安全运营；协同 R2 架构负责人、R3 DBA
- 核心观点：身份校验、访问来源控制和传输链路保护分别解决不同问题，需要在数据库访问路径上协同配置，不能相互替代。
- 状态：文章 V0.1 初稿；内部审阅稿，未经技术/业务审核及发布审批。

## 论证结构
1. 从账号、网络和加密配置分散切入；
2. 区分客户端/应用/数据库/最终用户身份；
3. 解释来源控制的作用与 IP 识别边界；
4. 解释代理架构下链路分段保护；
5. 对应 DBPrisma 身份校验、IP 名单和国密链路能力；
6. 给出企业访问路径检查问题。

## 主张与事实状态

| 主张 | 类型 | 边界 |
| --- | --- | --- |
| DBPrisma 可接管客户端身份校验 | 产品事实 | 按现行口径表达 |
| 应用层账号与数据库底层账号物理隔离 | 产品事实 | 不等同于识别最终自然人 |
| DBPrisma 提供 IP 地址允许名单/拒绝名单 | 产品事实 | 黑白名单仅针对 IP 地址，不针对 SQL 语句 |
| DBPrisma 支持数据库链路国密加密 | 产品事实 | 不擅自扩展为端到端全链路 |
| 身份、来源、链路保护不可互相替代 | 安全架构判断 | 可作为方法论表达 |
| IP 地址不等于真实用户身份 | 技术边界 | 必须保留 |

## 禁止延伸
- 不得把应用层账号直接称为最终用户身份；
- 不得声称 IP 地址可证明真实身份或业务目的；
- 不得在未核验时宣称客户端至网关、网关至数据库两段均默认加密；
- 不得将支持国密加密扩大为任意算法、协议或密码模块认证承诺；
- 不得声称身份、来源和链路控制覆盖数据库全部安全风险。

## 发布前确认
1. 身份校验流程及应用层/数据库层账号映射机制；
2. IP 地址黑白名单的作用位置、来源地址识别和代理部署拓扑要求；
3. 国密加密覆盖的具体链路段、协议和配置条件；
4. 证书/密钥管理及部署责任边界；
5. 对应版本的配置界面、配置项或演示证据。
