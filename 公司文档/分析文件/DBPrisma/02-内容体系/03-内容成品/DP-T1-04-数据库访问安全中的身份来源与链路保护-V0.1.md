# 数据库访问安全中的身份、来源与链路保护

> 文章定位：技术解释型 + 场景方案型  
> 选题编号：DP-T1-04  
> 版本：V0.1 初稿  
> 状态：内部审阅稿，未经发布审批

数据库访问安全经常被拆成几个独立配置：账号密码由应用团队管理，访问地址由网络团队维护，传输加密由基础设施团队配置，数据库账号权限则由 DBA 负责。

这种分工本身并没有问题。真正需要关注的是，这些控制是否能够共同回答三个基础问题：谁在访问数据库？访问从哪里发起？访问请求在传输过程中是否受到适当保护？

身份、来源和链路保护并不是同一项技术，但它们共同构成数据库访问路径安全治理的重要部分。

## 一、身份：连接使用的账号不一定等于实际操作人

数据库连接通常需要使用账号和凭据完成认证。但在企业应用中，多个业务用户可能通过同一个应用服务账号访问数据库。数据库看到的账号，可能只能说明应用使用了哪个数据库身份，并不能直接说明具体是哪位业务用户触发了操作。

因此，企业需要区分不同层次的身份：

- 发起数据库连接的客户端或应用；
- 连接使用的应用层账号；
- 数据库后端实际使用的数据库账号；
- 业务系统中触发操作的最终用户。

这些身份之间可能存在映射关系，但不能默认完全等同。若企业希望审计记录能够关联到最终业务用户，还需要应用系统提供相应上下文，并明确传递和验证方式。

在数据库访问入口建立身份校验和账号隔离机制，可以帮助企业集中管理连接身份，减少应用侧账号与数据库底层账号直接混用带来的治理困难。但它不能凭空推断应用内部的最终用户身份。

## 二、来源：知道账号，还需要知道连接从哪里进入

仅有账号信息并不足以完整描述一次访问。相同的账号可能从不同主机、网段或应用环境发起连接。

来源控制的意义，是把访问入口与允许的网络来源建立明确关系。例如，企业可以根据业务部署和网络分区，配置允许访问的来源范围，并对不符合规则的连接进行限制。

来源控制需要与网络架构和实际部署相匹配。IP 地址可以提供来源线索，但并不天然等同于真实用户身份，也不能单独证明请求具有合法业务目的。企业仍需结合身份认证、数据库权限和应用安全控制进行判断。

## 三、链路：身份可信还需要传输过程受到保护

数据库请求在客户端、代理入口和数据库之间传输。若传输链路缺乏适当保护，凭据或业务数据可能面临被窃听、篡改等风险。

因此，企业需要根据安全要求和部署环境选择适当的传输保护方式，并明确加密覆盖的具体链路段、协议配置、证书或密钥管理责任。

尤其在存在代理网关时，应分别确认客户端到网关、网关到数据库的连接配置。不能仅凭其中一段链路启用了加密，就推断整个访问路径都已受到相同保护。

## 四、身份、来源和链路需要协同治理

身份回答“使用什么身份”，来源回答“从哪里连接”，链路保护回答“请求如何安全传输”。三者相互补充，但不能互相替代。

例如，来源地址符合允许名单，并不代表连接身份一定可信；账号认证成功，也不代表请求来源符合企业策略；链路加密可以保护传输过程，但不能判断 SQL 请求是否符合业务规则。

因此，数据库访问治理应把身份校验、来源控制、传输保护与 SQL 请求检查、数据库原生权限和行为审计结合起来考虑，并明确各层控制的责任边界。

## 五、DBPrisma 如何参与这三类控制

DBPrisma 部署在现有数据库前，通过代理入口承接客户端数据库访问请求。

在身份方面，DBPrisma 可接管客户端身份校验，实现应用层账号与数据库底层账号的物理隔离。这里的应用层账号与最终业务用户身份仍应区分，若需要关联最终用户，应由业务系统提供相应身份上下文。

在来源方面，DBPrisma 提供基于 IP 地址的允许名单和拒绝名单，用于控制访问来源。这里的黑白名单针对的是 IP 地址，不是 SQL 语句，也不是 SQL 防火墙的 SQL 规则。具体规则需要结合网关部署位置、网络拓扑和客户端实际来源地址进行配置。

在链路保护方面，DBPrisma 支持数据库链路国密加密。项目实施时，应核对客户端至网关、网关至数据库的具体连接方式及加密配置，不能将某一段链路的配置直接等同于端到端保护。

这三类能力与 SQL 防火墙、访问控制和行为审计共同构成数据库访问路径上的安全治理能力。它们提供的是访问入口处的控制和观察能力，并不替代数据库原生权限、网络分区、企业身份管理或应用自身安全机制。

## 六、企业可以怎样检查现有访问路径

- 是否明确区分客户端、应用账号、数据库账号和最终业务用户？
- 应用账号与数据库底层账号是否有清晰的隔离关系？
- 是否掌握各类数据库连接的真实来源地址？
- 访问来源允许和拒绝规则是否经过梳理和验证？
- 是否明确客户端到代理、代理到数据库的链路保护配置？
- 加密协议、证书或密钥的管理责任是否清楚？
- 身份、来源和链路策略变更是否有测试、审批和审计记录？

**数据库访问安全不能只看账号是否正确，还要同时理解访问来源和传输链路。** DBPrisma 在数据库前提供身份校验、访问来源控制和数据库链路国密加密能力，为企业在统一访问入口落实相关策略提供技术支撑。实际保护范围仍以部署拓扑、产品版本和配置验证结果为准。
