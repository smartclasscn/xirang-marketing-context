## 一、能力域 E/F 调整

原 E、F 顺序调整如下：

- **E：管理、监控与自动化接口。** 管理、监控与自动化接口已经实现，归入当前已实现能力域。
- **F：SQL 解析与处理基础。** SQL Parser 等 SQL 解析基础能力归入 F。
- **A—E：** 作为当前已实现能力域组织；具体单项能力仍按能力地图中的“已实现/支持/可扩展”状态和技术确认边界表述。
- **G：** AI 接口预留与智能化扩展。当前仅预留 AI 接入钩子，AI 功能尚未实现。
- **SQL 方言转换：** 继续作为独立、未开发的可扩展方向，不并入当前已实现能力域，也不与 SQL Parser 或 SQL 防火墙混为一谈。

## 二、H4 调整：数据库并行验证与渐进式替代

H4 的主要场景明确为：应用连接协议/驱动适配和目标数据库 SQL/行为兼容条件满足后，利用 DBPrisma 的统一接入、多后端路由和流量采集审计，组织新旧数据库并行验证与分阶段替代。

必须区分两层兼容性：

1. **连接协议/驱动兼容：** 应用使用的驱动和连接协议必须处于对应 DBPrisma 产品当前适配范围。当前已知适配方向为 MySQL 与 PG。目标数据库支持 Oracle 兼容 SQL，不代表 DBPrisma 已支持 Oracle 驱动或连接协议。
2. **SQL 与数据库行为兼容：** 目标数据库对应用实际使用的 SQL、数据类型、函数、事务和会话行为应具备足够兼容性。

兼容性评估和 PoC 应尽量前置。无法通过现有适配、配置、目标数据库适配或应用调整解决的差异，可另行评估为技术工作；SQL 方言转换仍是未开发的独立扩展方向，不是 H4 当前方案的默认前提。

H4 主要能力组合为 A 统一接入 + B 多后端路由 + D 流量采集与行为审计。E 管理、监控与自动化接口可用于运行管理和外部集成。多后端写广播不是默认前提，且不等于数据复制或一致性保证。

## 三、H5 调整：同类数据库多实例统一接入与访问治理

当前 H5 聚焦多个同类数据库实例，例如多个 MySQL 协议兼容实例，或多个 PG 协议兼容实例。通过对应的 DBPrisma for MySQL 或 DBPrisma for PG 产品适配，在应用与多个同类数据库实例之间提供统一代理入口、后端路由和访问治理。

当前 DBPrisma 不是一个实例统一代理 MySQL、PG、MongoDB、向量数据库等不同数据库类型。跨数据库类型的统一接入与统一管理保留为未来扩展方向，需要增加相应协议适配能力，并研究跨产品统一管理体系。

## 五、未改变的边界

- 未修改正式对外口径、产品事实基线、术语台账、禁写清单、证据登记或 U6 授权状态。
- 未将 SQL 方言转换、跨数据库类型统一接入或 AI 功能写成当前已实现能力。
- 所有场景仍需按具体数据库、驱动、版本、部署模式和验证证据确认；本修订不构成客户项目兼容承诺。
