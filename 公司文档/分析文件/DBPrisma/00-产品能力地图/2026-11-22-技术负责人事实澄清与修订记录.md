## 一、已明确的当前产品事实

### 1. 黑白名单对象

DBPrisma 所称黑白名单针对 **IP 地址**，用于访问来源控制；不是针对 SQL 语句的黑白名单，也不是 SQL 防火墙规则的另一种称呼。

### 2. SQL 防火墙实现机制

DBPrisma 当前 SQL 防火墙采用 **正则表达式（Regular Expression）方式匹配 SQL 请求**，不是简单的字符串等值比较，也不是 AST 结构识别或语义识别。

对外或内部技术材料应准确区分：
- 字符串等值比较：不是当前采用的方式；
- 正则表达式规则匹配：当前 SQL 防火墙的实现方式；
- AST 结构识别：不是当前 SQL 防火墙实现方式；
- 语义识别：不是当前 SQL 防火墙实现方式。

不得因为产品具有 SQL 解析相关基础，就将当前 SQL 防火墙描述成 AST 或语义识别型防火墙。技术负责人提到目前业内较多方案采用正则表达式；负责人回忆此前调研 ProxySQL 时也见过正则表达式方式。ProxySQL 这一行业参照仅记录为负责人的调研记忆，尚未独立核验，不作为本产品事实证据或对外比较结论。

### 3. AST 与语义相关能力

语义识别与 AST 相关能力可以进一步研究和实现，但拟放在 **SQL 方言转换**方向中开展，不属于当前 SQL 防火墙实现。技术负责人指出这部分有一定难度。

负责人原话中使用了“语音识别”一词。该术语在 SQL 方言转换语境下的准确含义尚待确认，现阶段不将其擅自改写为“语义识别”，也不将其列为当前能力或宣传主张。AST 与语义识别作为未来方向保留。

### 4. 集群模式

- **串行集群：当前支持。**
- **并行集群：当前暂不支持，但技术上可以进一步开发。**

并行集群应列为未来可扩展方向，不得写成当前已支持能力。串行集群的具体部署拓扑、节点关系、故障切换和一致性边界仍需按产品版本核验。

### 5. AI 接入状态

DBPrisma 已预留 AI 接入钩子（hooks），但 **当前并没有完成 AI 功能开发或实际接入**。

因此，下列能力均不能写成当前已实现或当前支持：
- AI 模型接入；
- SQL 或行为数据的 AI 分析、训练；
- AI 辅助配置；
- AI 运行优化；
- AI 自动化管理或智能运维。

这些只能作为未来扩展方向。当前准确表述为“已预留 AI 接入钩子，AI 功能尚未实现”。

## 三、后续统一表达规则

- “黑白名单”必须明确写为“IP 地址黑白名单”或“IP 访问来源控制”。
- SQL 防火墙必须明确当前采用正则表达式规则匹配，不得写成字符串等值比较、AST 识别或语义识别。
- AST 与语义识别放在 SQL 方言转换的未来技术方向，不得并入当前 SQL 防火墙能力。
- 集群能力必须区分串行集群（当前支持）与并行集群（当前不支持、未来可开发）。
- AI 只能表述为预留接入钩子，当前 AI 功能尚未实现。
- ProxySQL 的正则表达式实现记忆未经独立核验，不作为对外竞品结论。
