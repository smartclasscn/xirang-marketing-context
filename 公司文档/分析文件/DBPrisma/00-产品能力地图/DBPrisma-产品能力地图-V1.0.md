## 1. 产品定位与能力总览

### 1.1 产品定位

DBPrisma（息壤数据库串行审计安全网关）部署在现有数据库前端，作为数据库访问路径中的统一入口。产品围绕数据库访问代理与连接治理、数据库安全防护、数据库流量采集与行为审计三个方向形成能力集合。

DBPrisma 不只是数据库代理，也不只是审计工具或 SQL 防火墙。其产品价值在于把数据库访问接入、身份与连接治理、安全控制、流量处理、审计分析和后续智能化应用放在同一条数据库访问链路及其管理体系中。

### 1.2 产品能力结构

| 一级能力域 | 定位 | 核心价值 |
| --- | --- | --- |
| A. 数据库接入代理与连接治理 | 数据库访问统一入口 | 在业务应用与现有数据库之间建立代理接入，统一管理连接与访问路径 |
| B. 数据库流量路由与运行保障 | 数据流向与后端运行管理 | 按规则分配数据库流量，支持读写分离、多后端处理及异常后端隔离 |
| C. 数据库安全防护 | 数据库访问链路上的主动防护 | 对连接来源、身份、传输链路、连接行为和 SQL 请求实施安全控制 |
| D. 数据库流量采集与行为审计 | 数据库访问过程的可观测与追溯 | 获取 SQL 与访问行为信息，形成审计记录和可供外部系统处理的数据 |
| E. SQL 解析与语义处理 | 跨能力域的基础技术能力 | 为 SQL 防护、路由、采集、审计、分析及业务理解提供 SQL 处理基础 |
| F. 管理、监控与自动化接口 | 产品运行管理与外部集成 | 提供配置、状态、指标、命令管道及程序化控制能力 |
| G. AI 接口与智能化扩展 | 将数据库访问数据转化为智能应用能力 | 在产品各层接入 AI 能力，利用 SQL 与行为数据开展分析、辅助管理和自动化 |
| H. 上层业务应用与行业场景 | 基于核心能力形成的解决方案方向 | 支持数据库访问治理、审计分析、迁移治理、遗留系统分析和业务孪生等场景 |

A—D 是产品直接面向客户的核心能力域；E 是跨能力域的 SQL 解析与语义基础；F 是管理与自动化接口；G 是智能化扩展方向；H 是基于产品能力形成的市场应用方向。SQL 方言转换单独列为可扩展方向，不纳入当前已实现能力。它们不是相互排斥的独立产品，也不代表每个场景都已形成标准化交付包。

## 2. 能力状态与宣传用语

本地图按以下口径描述能力：

| 状态 | 含义 | 宣传表达建议 |
| --- | --- | --- |
| 已实现 | 负责人已明确确认产品具备该项实现；相关细节可另标技术人员确认 | 使用“实现”“具备”等表达，描述具体能力，不扩展未经确认的指标和边界 |
| 支持 | 产品能力可用于承载、适配或实现某类场景；不表示该场景已经完成客户验证或形成标准交付 | 使用“支持”“可用于”“可面向”等表达 |
| 可扩展方向 | 已有技术基础或接口路径，可进一步扩展形成能力或解决方案 | 使用“可扩展”“可结合”“可进一步用于”等表达 |
| 需技术确认 | 需要技术人员确认具体模块、实现路径、配置条件、兼容范围或版本边界；不否定负责人已确认的产品能力 | 内部标注，不必在对外文案中将其写成产品缺陷或未实现 |
| 规划/探索 | 尚处于方案或探索阶段 | 仅用于内部路线图；不得写成当前已实现能力 |

“实现”与“支持”不是简单的强弱等级。“实现”描述产品已经具备的具体功能；“支持”描述产品能够承载的技术范围或应用场景。市场内容可以先从场景和客户问题切入，再根据具体主张选择准确动词，不因某项场景尚未形成完整交付包而停止内容规划。

## 3. 核心能力地图

### A. 数据库接入代理与连接治理

**能力目标：** 在不要求业务系统重写数据库访问逻辑的前提下，将数据库访问统一接入 DBPrisma，由网关承接连接、认证和访问路径管理。

| 能力项 | 能力说明 | 状态 | 技术确认标注 |
| --- | --- | --- | --- |
| 数据库前置部署 | DBPrisma 部署在现有数据库前端，成为应用访问数据库的统一入口 | 已实现 | 确认当前产品版本及部署拓扑边界 |
| 业务应用接入 | 通过调整数据库连接地址接入网关，不要求改写原有业务应用代码 | 已实现 | 不同驱动、连接池及连接特性的适配边界需按目标环境确认 |
| 认证托管 | 由网关承接客户端身份校验，实现应用层账号与数据库底层账号的隔离 | 已实现 | 认证流程、凭据映射和后端账号管理细节需技术确认 |
| 透明透传 | 提供透明透传接入模式，使业务连接经过网关到达后端数据库 | 已实现 | 与认证托管模式的能力差异及 TLS 条件需结合部署方式说明 |
| 连接池管理 | 对后端数据库连接进行池化管理 | 已实现 | 池化粒度、连接复用条件和会话状态约束需技术确认 |
| 连接多路复用 | 管理客户端连接与后端连接之间的复用关系 | 已实现 | 多路复用适用条件及事务/会话状态限制需技术确认 |
| 统一入口治理 | 将原本分散在应用与数据库之间的访问连接收口到网关 | 已实现 | 对外表达不扩展为“无需任何配置” |

**市场价值：** 企业可以在尽量不触碰既有业务代码的情况下增加数据库访问控制、审计和路由能力；也可以先接入网关，再逐步推进安全治理和数据库替代工作。

### B. 数据库流量路由与运行保障

**能力目标：** 对进入网关的数据库流量进行识别、分发和后端运行管理，使数据库访问路径具备可配置的流量治理能力。

| 能力项 | 能力说明 | 状态 | 技术确认标注 |
| --- | --- | --- | --- |
| 数据路由 | 根据配置和路由规则将数据库请求分发至目标后端 | 已实现 | 路由条件、SQL 类型及会话约束需技术确认 |
| 读写分离 | 将读请求与写请求按规则分配至不同后端路径 | 已实现 | 事务一致性、读后写、会话粘滞及故障场景需技术确认 |
| 多后端写广播 | 将写操作按配置广播至多个后端 | 已实现 | 广播范围、失败处理、顺序和一致性语义需技术确认；宣传不得直接等同于数据库复制或迁移完成 |
| 负载分配 | 在多个后端之间按策略分配流量 | 已实现 | 权重、健康状态与具体算法需技术确认 |
| 后端健康管理 | 监控后端状态，识别不可用或异常后端 | 已实现 | 探测机制、阈值和恢复条件需技术确认 |
| 熔断与故障隔离 | 对异常后端实施隔离，降低单一后端故障对访问路径的影响 | 已实现 | 熔断状态机及边界条件需技术确认 |
| 健康后端切换 | 主后端不健康时，新连接可转向健康后端 | 已实现 | 该描述限定为新连接；已有连接、事务和会话迁移行为需技术确认 |

**市场价值：** 统一管理多后端访问路径，为业务读写分流、数据库运行治理、迁移并行运行等场景提供基础。

### C. 数据库安全防护

**能力目标：** 在数据库访问入口建立多层安全控制，将连接准入、身份认证、传输加密、连接限制和 SQL 防护组合起来。

| 能力项 | 能力说明 | 状态 | 技术确认标注 |
| --- | --- | --- | --- |
| IP 访问控制 | 通过 IP 允许名单和拒绝名单控制访问来源 | 已实现 | 支持的地址格式、规则优先级及动态生效方式需技术确认 |
| TLS 链路保护 | 支持客户端至网关、网关至数据库两段链路的 TLS 配置 | 已实现 | TLS 终结、透传和两段链路组合行为按部署模式确认 |
| 国密传输 | 支持基于铜锁（Tongsuo）的 TLCP 与国密 TLS 1.3 相关配置，使用 SM2/SM3/SM4 算法 | 已实现 | 具体密码套件、协议组合、证书要求和适配环境需技术确认 |
| 代理身份认证 | 通过代理用户体系实施客户端身份校验 | 已实现 | 认证托管与透明透传模式下的认证责任边界需技术确认 |
| 认证失败限制 | 对认证失败行为实施速率限制或封禁 | 已实现 | 阈值、窗口、封禁时长及例外规则需技术确认 |
| 单 IP 连接配额 | 限制单一 IP 的连接数量 | 已实现 | 配额统计范围及超限行为需技术确认 |
| SQL 防火墙 | 对 SQL 请求实施规则检查，并按策略记录或拦截 | 已实现 | 负责人已确认产品具备完整 SQL Parser；防火墙规则引擎是否及如何使用 Parser 结果，需技术确认 |
| 预编译语句防护 | 对预编译语句在 PREPARE 与 EXECUTE 等阶段实施检查 | 已实现 | 当前用户手册描述了两阶段检查；规则更新、参数内容和长数据参数的边界需技术确认 |
| 黑白名单策略 | 根据配置的 SQL 规则实施放行或拦截 | 已实现 | 规则匹配机制、优先级、白名单语义及与 Parser 的关系需技术确认 |

**市场价值：** 将数据库访问安全从数据库外围或应用代码中的分散控制，前移到数据库访问路径的统一入口。

**宣传边界：** 可围绕数据库入口安全、SQL 防火墙、访问控制和国密链路保护展开；不得未经确认写成覆盖所有 SQL 风险、完全阻断 SQL 注入、表级/列级权限控制或替代所有安全产品。

### D. 数据库流量采集与行为审计

**能力目标：** 对经过网关的数据库访问过程进行采集和记录，使 SQL 行为具备可观测、可追溯、可导出的数据基础。

| 能力项 | 能力说明 | 状态 | 技术确认标注 |
| --- | --- | --- | --- |
| SQL 流量采集 | 获取经过网关的 SQL 请求及相关访问信息 | 已实现 | 不同接入模式、加密链路和采集位置的可见范围需技术确认 |
| SQL 类型识别 | 对 SQL 类型进行分类，支持按类型筛选采集 | 已实现 | 分类覆盖范围和特殊语句处理需技术确认 |
| 行为审计记录 | 记录 SQL、访问身份、来源、时间、目标后端及执行结果等信息 | 已实现 | 不同输出接口的字段完整性和版本差异需技术确认 |
| 执行耗时记录 | 记录 SQL 执行耗时，可用于慢查询识别与运行分析 | 已实现 | 耗时口径、采样方式及慢查询阈值需技术确认 |
| SQL 字面量脱敏 | 对审计输出中的 SQL 字面量实施脱敏处理 | 已实现 | 脱敏覆盖范围、例外项和各输出路径的一致性需技术确认 |
| 审计日志输出 | 支持将采集数据输出为结构化记录 | 已实现 | 当前用户文档描述 NDJSON；产品说明另列 JSON/NDJSON、CEF、Syslog，格式与版本对应关系需技术确认 |
| 外部审计系统对接 | 采集数据可供客户现有 SIEM、SOC 等系统接收和处理 | 支持 | 具体接口、字段映射、传输方式和客户系统适配需按项目确认 |
| 审计数据完整性 | 可扩展使用哈希链等方式增强审计记录完整性 | 支持 | 相关能力的产品版本、启用方式和验证依据需技术确认，不作为默认能力泛化宣传 |

**市场价值：** 从“数据库发生了什么”延伸到“谁在什么时间、从哪里、对哪个数据库执行了什么操作、结果如何”，为安全审计、运行分析和业务行为理解提供数据基础。

### E. SQL 解析与语义处理

**能力目标：** 通过完整 SQL 解析能力理解数据库请求，为防护、路由、采集、审计和上层应用提供统一的 SQL 处理基础。

| 能力项 | 能力说明 | 状态 | 技术确认标注 |
| --- | --- | --- | --- |
| 完整 SQL Parser | DBPrisma 具备完整 SQL 解析能力，相关技术由息壤自主研发的数据库内核及 XRQL 相关技术支撑 | 已实现 | 由技术人员确认当前 DBPrisma 所覆盖的 SQL 方言、语法版本及边界 |
| SQL 语法结构识别 | 对 SQL 语句进行语法解析，而非仅依赖文本片段判断 | 已实现 | Parser 输出的数据结构、错误恢复及不完整语句处理需技术确认 |
| SQL 类型与结构信息 | 为后续模块提供 SQL 类型和结构化信息 | 已实现 | 各模块是否统一复用同一解析结果需技术确认 |
| SQL 语义理解 | 为 SQL 防护、路由、行为分析及业务逻辑理解提供语义基础 | 已实现 | 当前语义覆盖范围与各模块使用深度需技术确认 |


**特别说明：** 安全加固指南中关于 SQL 防火墙规则子串匹配的描述，只描述特定规则匹配方式，不等同于 DBPrisma 不具备完整 SQL Parser。完整解析能力与防火墙规则匹配引擎之间的调用关系，作为技术确认事项记录，不改变负责人对完整 SQL Parser 的事实确认。

### E-扩展方向. SQL 方言转换

SQL 方言转换是一个独立且较大的技术方向，不与 SQL Parser 或 SQL 语义解析能力合并表述，也不作为当前已开发能力列入产品功能清单。当前将其保留在产品能力地图和市场场景规划中，定位为基于 SQL 解析能力可进一步研究和扩展的方向。

| 能力项 | 能力说明 | 状态 | 技术确认标注 |
| --- | --- | --- | --- |
| SQL 方言转换 | 面向不同数据库 SQL 方言之间的语法、函数、数据类型及语义差异，探索转换与适配能力 | 可扩展方向（未开发） | 仅确认技术可扩展性、目标数据库范围、转换边界和独立工作量；不得标记为已实现或当前支持能力 |

**边界：** 当前 DBPrisma 具备完整 SQL Parser 是已确认事实；这不代表已经开发 SQL 方言转换。解析是理解 SQL 的基础能力，方言转换还涉及源/目标方言映射、函数与类型适配、事务语义及执行结果差异，应作为独立能力建设。

### G. AI 接口与智能化扩展

**能力目标：** 将 AI 接入 DBPrisma 的不同处理层，使数据库访问数据不仅用于记录和展示，也可进一步用于分析、辅助决策、配置优化和自动化管理。

负责人确认的产品方向与事实：

1. DBPrisma 各层均可接入 AI 接口。
2. 网关获取的 SQL 与访问行为数据，可用于训练、分析和理解数据库访问行为。
3. AI 分析或训练结果可进一步用于产品配置、运行优化和自动化管理。
4. AI 能力可与 SQL 解析、防护、路由、采集审计及管理接口结合，不限定为单一独立模块。

| 能力项 | 能力说明 | 状态 | 技术确认标注 |
| --- | --- | --- | --- |
| 分层 AI 接口 | 产品各处理层可接入 AI 接口 | 已实现/可接入 | 接口规范、调用生命周期、数据契约及各层覆盖范围需技术确认 |

## 4. 上层业务应用与市场场景地图

以下场景是基于 DBPrisma 核心能力形成的市场应用方向。场景可以先于完整产品化方案开展市场传播；对外使用“支持”“可用于”“面向”等表达，不把场景支持误写成已完成客户交付。

### H1. 数据库访问安全治理

- **客户问题：** 数据库访问入口分散，账号权限难统一，SQL 风险难在数据库入口处控制。
- **能力组合：** A 接入代理 + C 安全防护 + D 行为审计 + F 管理监控。
- **可传播价值：** 在现有数据库前增加统一访问入口，支持来源控制、身份校验、SQL 防护和行为追溯。
- **推荐表达：** “DBPrisma 支持在现有数据库前建立统一安全访问入口，实现数据库访问控制、SQL 防火墙与行为审计。”
- **技术确认：** 目标数据库、接入模式、身份映射和安全规则范围。

### H2. 数据库行为审计与运行分析

- **客户问题：** 业务系统和数据库之间缺少完整的 SQL 行为记录，故障定位、安全审计和业务分析依赖人工排查。
- **能力组合：** D 流量采集与审计 + E SQL 解析 + F 数据输出与监控 + G AI 分析。
- **可传播价值：** 支持采集 SQL、身份、来源、时间、目标后端、执行结果和耗时等信息，形成可供审计和分析的数据基础。
- **推荐表达：** “DBPrisma 支持对数据库访问行为进行采集与审计，为安全追溯、运行分析和业务行为理解提供数据基础。”
- **技术确认：** 字段覆盖、采集完整性、数据保留、脱敏与外部系统接口。

### H3. 数据库连接治理与访问路径统一

- **客户问题：** 多应用、多数据库、多后端之间连接配置分散，连接池和连接状态缺乏统一治理。
- **能力组合：** A 连接代理与连接池 + B 路由 + F 管理监控。
- **可传播价值：** 通过统一入口管理数据库连接、后端连接和访问路径。
- **推荐表达：** “DBPrisma 支持将分散的数据库访问连接收口到统一网关，集中管理连接与流量路径。”
- **技术确认：** 连接复用条件、连接池参数、会话状态及高并发运行边界。

### H4. 数据库迁移与渐进式替代

- **客户问题：** 数据库替代往往要求一次性切换，业务连续性、数据一致性和迁移风险难以控制。
- **能力组合：** A 统一接入 + B 多后端路由与写广播 + D 流量采集审计 + E SQL 处理。
- **可传播价值：** 支持在现有业务访问路径上增加网关，结合多后端访问和流量治理，为数据库并行运行、验证和渐进式替代提供技术路径。
- **推荐表达：** “DBPrisma 支持数据库迁移过程中的统一接入与多后端流量治理，可用于构建数据库并行验证和渐进式替代路径。”
- **技术确认：** 数据同步语义、写广播一致性、增量追平、冲突处理、切换和回退策略。具体迁移方案需按数据库类型与项目条件设计。
- **边界：** 不将“支持渐进式迁移”表述成“自动完成异构数据库无损迁移”。

### H5. 异构数据库统一接入与并发访问

- **客户问题：** 一个业务系统或平台需要在统一访问入口下管理不同类型的数据库连接与后端访问路径。
- **能力组合：** A 统一接入 + B 路由 + F 管理与接口集成。
- **可传播价值：** 通过统一代理入口和路由治理，支持不同类型数据库的统一接入与访问路径管理；数据库本身的 SQL 方言差异仍由业务或适配层处理。
- **推荐表达：** “DBPrisma 支持多类型数据库的统一接入与访问路径治理，为异构数据库环境下的访问管理提供统一入口。”
- **技术确认：** 目标数据库协议兼容范围、连接行为、路由策略和并发访问模型。
- **边界：** 统一接入不等于 SQL 方言自动转换，不笼统宣称“全面兼容所有数据库”。

### H5-扩展场景. SQL 方言转换

- **客户问题：** 数据库替代、异构数据库整合或应用迁移时，源数据库与目标数据库之间存在 SQL 语法、函数、数据类型及执行语义差异。
- **能力基础：** E 完整 SQL Parser；未来需独立建设方言规则、语法树转换、函数/类型映射及语义适配能力。
- **当前定位：** 可扩展方向，尚未开发，不属于 DBPrisma 当前已实现或支持的功能。
- **市场推进：** 保留场景研究、客户需求识别和解决方案规划；不得使用“DBPrisma 已实现/支持 SQL 方言转换”的表达。
- **推荐表达：** “DBPrisma 已具备完整 SQL 解析能力，SQL 方言转换可作为后续面向异构数据库迁移与整合场景的扩展方向。”

### H6. 遗留系统分析、维护与升级改造

- **客户问题：** 原开发团队解散、文档缺失或业务逻辑长期沉淀在程序中的系统难以维护，升级改造前缺少可靠的业务行为认知。
- **能力组合：** D SQL 流量采集 + E SQL 解析与语义处理 + G AI 分析。
- **可传播价值：** 通过采集和分析真实数据库访问 SQL，帮助理解遗留系统的数据访问行为、业务操作路径和数据库依赖，为系统接管、维护、升级改造提供依据。
- **推荐表达：** “DBPrisma 支持基于 SQL 访问行为分析遗留系统的数据访问逻辑，为软件维护和升级改造提供分析依据。”
- **技术确认：** SQL 与业务操作关联、动态 SQL 处理、调用方识别、业务语义归纳及 AI 分析结果的准确性。
- **边界：** 不宣称仅凭 SQL 即可完整还原全部业务逻辑、源代码或业务需求。

### H7. 业务孪生与数据访问行为建模

- **客户问题：** 企业业务运行过程难以从数据库层面持续观察，业务流程、数据变化与系统执行行为之间缺少关联。
- **能力组合：** D 行为采集 + E SQL 语义处理 + G AI 分析 + F 数据接口。
- **可传播价值：** 支持以数据库访问行为为基础，持续积累业务操作、数据访问和执行结果信息，为业务过程建模、业务孪生和运行分析提供数据来源。
- **推荐表达：** “DBPrisma 支持采集和分析数据库访问行为，可为业务孪生及业务运行过程建模提供数据基础。”
- **技术确认：** 业务实体映射、事件关联、状态还原、跨系统关联、模型更新和孪生结果验证。
- **边界：** DBPrisma 提供数据采集与分析基础，不将完整业务孪生平台描述为 DBPrisma 当前独立功能。

### H8. AI 驱动的数据库治理与软件理解

- **客户问题：** 数据库安全、运行管理和遗留软件维护需要大量人工分析，现有日志和监控数据难以直接形成治理动作。
- **能力组合：** A—F 核心能力 + G 分层 AI 接口。
- **可传播价值：** 支持将 SQL 与行为数据用于 AI 分析，并将分析结果进一步连接配置、优化和自动化管理。
- **推荐表达：** “DBPrisma 支持将数据库访问数据接入 AI 分析流程，并为配置优化、运行治理和自动化管理提供扩展接口。”
- **技术确认：** AI 接口覆盖范围、数据上下文、模型接入方式、执行权限、人工确认和审计机制。
- **边界：** 不把“可接入 AI”直接等同于“已实现自主决策、自主修复或全自动数据库运维”。

## 5. 能力之间的关系

DBPrisma 的核心价值不是单项功能的简单叠加，而是形成一条可组合的访问与治理链路：

1. **接入：** 应用连接进入 DBPrisma，建立统一入口。
2. **身份与准入：** 根据接入模式进行身份校验，并实施来源和连接控制。
3. **SQL 处理：** 对请求进行解析和处理，为防护、路由、采集等环节提供基础。
4. **安全防护：** 按规则决定请求是否放行、记录或拦截。
5. **流量路由：** 将请求分配到目标数据库后端。
6. **行为采集：** 获取 SQL、访问上下文、耗时和执行结果等信息。
7. **管理与输出：** 通过管理接口、指标和数据管道供运维及外部系统使用。
8. **AI 扩展：** 将访问数据和分析结果反馈到配置、优化与自动化管理环节。

上述顺序用于说明产品逻辑关系，不意味着每种部署模式都具有完全相同的数据可见性或处理顺序。透明透传、TLS 终结、SQL 可见性和采集能力之间的具体关系，按实际部署条件说明。
